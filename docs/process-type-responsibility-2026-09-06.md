# 加工種別の確定責任と処理経路

## 1. 方針

加工種別は価格比較の前提条件である。AIまたは営業担当者が根拠なく確定してはならない。候補提示と最終確定を分離し、確定者・根拠・ルール版を記録してから類似案件検索と価格比較へ進む。

## 2. 確定経路

| 状況 | システムの処理 | 人間の役割 | 価格比較 |
| --- | --- | --- | --- |
| 商品マスタに確定済み加工種別が1つある | 商品マスタ値を取得して表示 | 営業が品番とマスタ行を確認 | 確認後に実行 |
| 同一顧客・品番・材質・数量の過去実績が2件以上あり、加工種別が1種類だけ | 過去見積番号、件数、加工種別を候補提示 | 営業が根拠を確認して採用 | 確認後に実行 |
| 過去実績に複数の加工種別がある | 全候補と根拠を表示し、営業による確定を拒否 | 技術担当が加工種別を確定 | 確定前は実行しない |
| 過去実績がない、または顧客・商品・材質・数量が不足 | 候補なし／条件不足を表示 | 技術担当が加工種別を確定。不足情報は営業が確認 | 確定前は実行しない |
| 新規特注品・加工方法不明 | 自動確定しない | 技術担当が図面、設備、工程、外注条件等を確認して確定 | 確定前は実行しない |

AIは候補説明に利用できるが、加工種別の最終決定者にはしない。

## 3. 現行データの制約

`20_商品マスタ.csv` の列は、`product_id`、`品番`、`商品名`、`材質`、`単位`、`廃番フラグ`、`備考`であり、加工種別列がない。そのため、現時点では商品マスタから加工種別を自動確定する経路は利用できない。将来この経路を使うには、正式な加工種別列、管理責任者、変更承認、適用開始日を追加する必要がある。

## TECH::MASTER回答による確定方針（2026-09-06）

TECH::MASTERから、配布CSVへ加工種別の列や仮の確定値を追加せず、「商品マスタに加工種別が存在しない」というデータ上の制約として扱うとの回答を得た。したがって、Lesson 4では次の現行処理を正式方針とする。

1. 商品マスタに確定値がある場合だけ、その値を候補として使用する。
2. 確定値がない場合は、同一条件の過去実績から加工種別候補を提示する。
3. 過去実績の加工種別が一意の場合も、自動確定せず、人間が見積番号と根拠を確認して記録する。
4. 複数候補・候補なし・条件不足の場合は、技術担当への確認として保留する。
5. 加工種別が確定するまで過去価格を比較しない。

この判断は、データ不足を受講者側の仮定で隠すのではなく、AI・ルールベース処理・人間判断の組合せを検証するためのものである。回答原文は2026-09-06にユーザーから提示されたTECH::MASTER回答を根拠とする。

## 4. 記録する項目

- 確定経路：商品マスタ、過去履歴、技術担当確定、技術確認待ち
- 加工種別（未確定時は空欄）
- 確定状態
- 確認者または記録者
- 根拠
- 参照した過去見積番号
- ルール版：`process-type-routing-1.0`
- 記録日時
- `final_decision_by_ai: false`

## 5. 実装上の安全措置

- 複数候補から営業が1件を選んで確定しようとすると、`PROCESS_TYPE_HISTORY_INVALID`で拒否する。
- 技術確認待ちでは類似見積を返さず、価格比較状態を`not_executed_process_type`とする。
- 承認判定では`PROCESS-001`により保留し、確認先を「技術担当」とする。
- 技術担当の回答後に再検索する際は、確認待ち時点の古い候補採否を消し、新しい検索結果について改めて人間が採否を記録する。
- 加工種別の候補検索・判定・保存はローカルDB内で行い、外部AIへ送信しない。

## 6. 検証結果

- 一意候補の正常例：京浜ロボティクス株式会社 埼玉工場／S45C-PIN-18／S45C／100個。過去見積2件がともに「樹脂切削」であり、営業確認後に価格比較、承認不要、見積回答予告下書き、人間の採用記録まで完走した。
- 複数候補例：ミナト医療機器／PPS-CVR-80／PPS／200個。板金2件、樹脂切削1件、短納期加工1件が存在した。営業による確定を拒否し、価格比較を実行せず技術担当へ保留した。その後、課題用の架空技術回答として「板金」を記録し、古い候補却下記録を消して再検索・再選択・承認再判定まで通した。
- 外部AI送信0回、自動メール送信なし。
