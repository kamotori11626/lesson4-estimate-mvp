## 2点の内容・原因・修正

| 不具合 | 確認できた原因 | 修正 |
| --- | --- | --- |
| 原文に材質の記載がないのに「材質が曖昧」と警告 | 正規化処理がAIのambiguousフラグを、該当項目の原文根拠を検証せず採用していた | 原文中の該当項目と曖昧表現の両方を検査。根拠なしのAI判定は採用せず、AMBIGUITY_UNVERIFIEDとして「情報不足（原文根拠未確認）」と確認行動を表示する |
| 寸法・公差を要確認としたが、引用・位置が空欄 | AIが引用を返さない場合に、明示された原文の該当箇所を照合・回復する処理がなかった | 「寸法と公差は前回同様です」を両項目の引用として保持。原文の位置[63,75)も保存し、引用が原文と一致することを検査する |

AIが内部でなぜその出力を選んだかは不明。保存していたのはアプリ正規化後の出力であり、Geminiの生応答そのものではない。過去結果から代表的な不合格パターンを再構成した回帰テストであり、生応答の完全再実行とは呼ばない。

## 追加対処方針の対応

| 方針 | 実装・検証内容 |
| --- | --- |
| 1. 情報不足と曖昧を区別 | 未記載、明示された不明・前回同様、根拠未確認のAI警告を別の理由として表示 |
| 2. 明確な項目は保持 | 一部項目に不確実性や矛盾があっても、明確な単一商品の品番などを保持。問題項目はnull・要確認 |
| 3. 複数商品は全体保留 | 複数商品・商品数不明は全項目を保留し、外部送信前に停止。単一商品に明示的に紐づく数量訂正だけを区別 |
| 4. 矛盾・訂正は自動採用しない | 「100個（訂正：200個）」等は両方の原文を表示し、数量は未確定。複数の材質・納期も自動選択しない |
| 5. 無効値・単位の扱い | 0・負数の数量や存在しない日付を拒否。単位未記載は推測せず、数値が明確なら数値だけ保持。kgをgと誤採用しない |
| 6. 原文根拠の検査 | 値・引用・位置を照合し、別項目の引用や存在しない引用を拒否。警告ごとに必要な確認行動を表示 |
| 7. 安全停止と障害の区別 | 許可済み匿名サンプル以外の外部送信を拒否。顧客欄を含む認証情報を保存・送信前に検査。API・出力形式・保存障害を業務上の情報不足と混同しない |

## 限界・業務上の未決定事項

- 引用回復は明示的な項目名付き文節を中心とした検査であり、任意の自由文を完全に理解するものではない。根拠を検証できないものは人間の確認へ回す。値自体を推測して補完しない。
- 対応単位は「セット、個、本、枚、台、組、式、箱、袋、kg、mm、g、m」。その他の単位が業務上誤りという意味ではない。自動採用の対応範囲外として確認を求め、単位換算は行わない。
- 明示的な単一商品の数量訂正だけは項目単位で保留する。複数商品か判断できない自由文は従来どおり全体保留。
- 正式な確認担当者・案件別必須項目・承認条件は未設定。画面上でその旨を明示し、すべて未確認下書きのままにしている。私の判断で正式担当者や承認条件を設定してはいない。
- 修正下書きを保存しても、初回の警告・原文根拠は監査上保持する。「確認済み」、後工程への確定引渡し、価格確定、納期確約、顧客送信は行わない。
- 1.1実Gemini再検証の全体合格2/3という過去結果は変更しない。1.2の実Gemini再検証は別途、回数と送信内容を限定して行う必要がある。
