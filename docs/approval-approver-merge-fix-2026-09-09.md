# 承認判定「確認先」複合条件修正記録

## 対象

- 教員確認日: 2026-09-09
- 対象機能: 承認要否判定
- 修正後ルール版: `approval-rules-0.2-draft`

## 確認された不具合

複数の保留理由と低粗利による管理職承認が同時に成立した場合、全体状態が `hold` になるため、`hold` のルールだけから確認先を作成していた。その結果、低粗利の `required` ルールが要求する「管理職」が確認先から欠落していた。

## 修正内容

- 全体状態の優先順位（`hold` → `required` → `not_required`）は変更しない。
- 確認先は、成立した `hold` と `required` の全ルールから和集合で作成する。
- 同じ確認先は重複表示しない。
- 表示順は「管理職 → 技術担当 → 購買・外注担当 → 業務責任者」とする。
- `no_trigger` のルールは確認先へ加えない。

## 回帰テスト

- 未確認項目あり + 加工種別未確定 + 粗利率10%: `hold`、確認先は「管理職、技術担当」。
- 価格比較不能 + 粗利率10% + 技術確認あり: `hold`、確認先は重複なしの「管理職、技術担当」。
- 技術確認のみ: `required`、確認先は「技術担当」。
- トリガーなし: 確認先なし。
