# 回答根拠・保留の解消状態・希望期間の記録機能

2026-09-01に実装し、通常のアプリ http://127.0.0.1:4173/ に反映した。
本機能は人間による確認の記録であり、正式な承認・納期保証・顧客送信ではない。

## 記録できること

| 対象 | 記録内容 |
| --- | --- |
| 回答根拠 | 回答者・役割、回答を確認した日時、資料番号・版、回答原文・確認内容、記録者、サーバー側の記録日時 |
| 項目ごとの状態 | 未確認／回答待ち／解消済み（記録）／今回不要（理由あり）、判断理由・確認先、対応する回答根拠 |
| 希望期間 | 未確認／単一日／希望期間を区別。期間は開始日・終了日を保持し、勝手に代表日へ変換しない |
| 履歴 | 保存時の修正前後値と確認記録の状態をDBに保持。画面には直近20回の履歴を表示 |

確認対象は抽出9項目に「商品・適用仕様の特定」「前回案件・変更有無」を加えた11項目。
11項目すべてが全案件で必須という意味ではない。案件別の正式な必須条件は未設定。

## 画面での使い方

1. アプリで「練習用の匿名サンプル」を選び、「ローカル簡易抽出」で抽出する。今回の練習にGemini送信は不要。
2. 抽出結果の下にある「回答根拠と現在の確認状態」へ進み、記録者名を入力する。
3. 「回答を追加する」の4欄に、回答者、確認日時、根拠資料、回答内容を入力する。練習では必ず「架空」と明記する。
4. 回答に基づく補足値は上の「抽出候補と原文の照合」へ記入する。原文の引用を回答内容に置き換えない。
5. 期間で回答された場合は「希望納期の形式」を「希望期間」にし、開始日・終了日を入力する。単一日の欄は空欄になる。
6. 「項目ごとの解消状態」で状態と判断理由を入力し、根拠のチェックを入れる。追加したばかりの回答は「今回追加する回答を根拠にする」を選ぶ。
7. 原文照合の確認にチェックし、「修正下書きを保存」を押す。
8. 保存成功の表示を確認してから「保存した結果を再表示」を押し、値・回答・状態・期間を照合する。

すでに保存した回答を使う場合は、「回答を追加する」の4欄を空欄にし、既存の回答根拠を選択する。回答の訂正は新しい回答を追記し、該当項目の根拠を付け替える。
「単一日」へ戻す場合は、先に希望納期の形式を切り替え、上の希望納期欄に日付を入力する。
「保存した結果を再表示」は現在表示中の案件を再取得する機能。過去案件を一覧から選び直す機能は今回の実装に含まない。

## 誤った確定を防ぐ制御

- 「解消済み」「今回不要」は、判断理由と同じ案件内の回答根拠がなければ保存できない。
- 「回答待ち」は確認先・確認事項の記入が必要。
- 解消済みの値・期間を変更し、判断理由と根拠を更新しなければ、保存時に該当項目を「未確認」に戻す。商品や仕様の変更では、商品特定・前回案件の判断も再確認対象になる。
- 空欄を解消済みにできない。ただし希望納期は、単一日が空欄でも有効な期間があり根拠がそろえば記録できる。
- 希望期間の逆転、不正な日付、受付日より前の期間、単一日との二重指定を拒否する。
- 回答日時は日本時間で入力し、受付日時以降・未来でない日時に限る。過去の資料作成日は根拠資料欄に記録する。
- 顧客名・数量・数量単位・商品特定を「今回不要」にできない。また入力済みの値を「今回不要」で隠すことはできない。
- 保存済み回答は追記式。別案件の回答ID、不正な状態、古い画面からの同時上書きを拒否する。
- 複数商品・対象外・処理エラーなどによる依頼全体の停止は、この記録で解除できない。

初回の抽出結果と人間の補足を分離し、新規抽出では初回スナップショットを保存する。
導入前の案件は初回スナップショットが存在しないため、修正後の値を初回値として捏造せず、取得できない旨を表示する。

## 限界・運用上の注意

記録者・回答者は自己申告であり、本人認証や正式な承認権限の確認は未実装。
記入した資料の実在性や回答の妥当性を、アプリが保証するわけではない。
「解消済み（記録）」を入力しても、抽出結果全体は未確認下書きのまま。価格確定・納期保証・後工程への確定引渡しは行わない。
回答情報を外部AIへ送る処理は追加していない。実業務データの利用には、従来どおり承認・セキュリティ整備が必要。

## 開発者向け

- `src/business-review.mjs`：記録形式、根拠の検証、期間の検証、再確認への戻し処理。
- `src/extraction-service.mjs`、`src/extraction-store.mjs`：取得・保存、同時更新制御、履歴のトランザクション保存。
- `public/index.html`、`public/extraction.js`、`public/styles.css`：入力・状態・根拠・履歴・期間の画面。
- `db/extraction.sql`：既存テーブルへ初回結果・確認記録の列を追加。既存値を上書きする移行は行わない。
- `tests/business-review.test.mjs`、`tests/extraction-store.test.mjs`：追加・回帰テスト。

このローカル環境ではDB列の追加とサーバー再起動は実施済み。
別環境へ反映する場合は、DB起動後に `npm run db:prepare-extraction` を実行し、サーバーを再起動する。原本CSVの再取込は不要。
