## 教材の構築手順との対応

1. To-Be業務フローとMVPスコープに沿い、見積依頼入力 → 情報抽出 → 人間の原文照合 → 名寄せ・類似案件検索 → 人間の候補判断 → 承認要否判定 → 文面下書き → 人間の文面判断、の順序にした。
2. 機能間の受け渡しを、抽出版、類似検索ID、承認判定IDで記録した。抽出結果の保存後に古い検索結果を使うこと、類似案件の採用・却下理由を保存せず承認判定へ進むことを拒否する。
3. 操作画面上部に、7段階の進捗、次に行うこと、該当箇所への移動、受け渡し値、結果一覧、保存ログ一覧を追加した。
4. 既存の `extraction_events`、`similar_search_events`、`approval_email_events` と下書き保存テーブルを統合表示する。新しい表示用APIは原文全体を返さず、統合表示自体は外部AIを呼ばない。
5. 通常のログイン済みChromeで、匿名サンプルとローカル処理のみを使って全工程を通した。
