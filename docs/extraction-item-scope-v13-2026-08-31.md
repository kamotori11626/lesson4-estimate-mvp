# 商品数と仕様不足の分離：修正版1.3

更新日：2026-08-31。今回のGeminiへの実送信は0回。

## 何を変更したか

1.2ではAIがscope=uncertainと返すと即座に全体保留となり、項目別の原文照合に進まなかった。1.3ではAIの判定とは別に、対応済みのラベル付き書式について本文全体を検査し、単一商品として扱える原文根拠を記録する。

| 条件 | 1.3の処理 |
| --- | --- |
| 複数商品・明示された商品数不明・対象外の事前検知 | 従来どおり全体保留。外部送信しない |
| AIがsingle | 従来のAI候補＋項目ごとの原文検査 |
| AIがuncertain、本文全体が対応済みの単一商品書式 | AIの不明判定を保存。AI候補は使わず、原文のローカル抽出で未確認下書きを作る。仕様不足・曖昧さは項目別に表示 |
| AIがuncertain、原文の単一商品根拠が不足／未対応の追記あり | SCOPE_UNCERTAINで全体保留。推測で1商品扱いにしない |
| AIがmultipleまたはout_of_scope | 単一商品に見える場合でも全体保留を維持 |

これはAIの判断そのものを正しくしたという主張ではない。AIが保留した場合にも、限定された原文書式から読める事実だけを下書きに残す処理である。追加のAI呼出し・自動再試行はない。

## 単一商品としてローカル処理できる条件

- 入力欄はsingleであること。ただし選択欄だけでは許可しない。
- 品名または品番が明示されていること。同じ種類のラベルの重複・商品列挙・前回一式等は許可しない。
- 本文の空白以外のすべての文・行が、対応する項目名付き記述か限定した挨拶・見積依頼文に一致すること。読み取れない部分を読み飛ばさない。
- 品名／品番は空白を含まない単一表記（文字・数字・ハイフン等）の対応範囲に限定する。A/B、AとB、A B、追加商品等は根拠として採用しない。
- 数量、単位、材質、寸法、公差、希望納期の値は対応済みの形式のみ。「不明」「前回同様」「来月半ば」等は仕様不足・曖昧さとして許容し、値を推測しない。
- 引用長の上限を超える記述は復元対象外。0数量・不正日付が対応書式に一致しても、既存の値検査でnullにする。

書式の対応範囲は保守的である。自由文、未知の注記、任意の日本語材質表現、スペースを含む品名など、業務上正しい内容でもローカル復元できない場合がある。その場合、AIがuncertainなら全体保留を続ける。この規則だけで自然文の商品数を完全判定できるとはしない。

明示された10商品・同一行の重複商品ラベル・A/B等の商品列挙・前回一式・別商品の参照も、事前の保留判定へ追加した。元の「複数商品は先頭だけ採用せず全体保留」という方針は維持している。

## 前回の不合格パターンに対する動作

「品名: MCナイロンプレート300」「数量: 1枚」「希望納期: 来月半ば」「寸法と公差は前回同様です」の入力で、AIがuncertain・全項目空欄を返すパターンを模擬した。

- 品名MCナイロンプレート300、数量1、単位枚を原文から下書きに残す。
- 材質・品番は情報不足。品名から材質を推測しない。
- 寸法・公差・希望納期はnullのまま、曖昧として原文を引用。
- 寸法・公差の引用は「寸法と公差は前回同様です」、位置[63,75)。
- LOCAL_SCOPE_FALLBACKの警告と、元のmodel_scope=uncertainを残す。
- すべてのconfidenceはnull、人間確認状態はpending。正式確認・後工程への引渡しは行わない。

モデルの生応答は保存していないため、過去のアプリ出力から分かる「uncertainによる全体保留」の代表パターンを模擬した。実Geminiの応答再取得でも、生応答の完全リプレイでもない。

## 監査・表示の変更

実行情報とDBのfinishedイベントに次を追加した。既存のJSONB列を使用し、DBのスキーマ変更・CSV再取込はしていない。

- scope_decision：元のモデル判定、ローカル判定の規則番号・理由・原文引用と位置、最終処理経路。
- extraction_method：gemini_fields / local_labelled_fallback / local_baseline / not_extracted。
- verified_external_response：正常なモデル応答を受けて形式検査したか。
- verified_external_extraction：1.3ではGemini候補の項目処理に進んだ場合のみtrue。ローカル代替・全体保留はfalse。trueも正答や人間確認済みを意味しない。

画面の実行情報に抽出方法を表示し、ローカル代替の場合は「AI抽出成功ではない」と明記した。今回Chromeでの画面操作は行っていない。配信された画面用スクリプトに変更が含まれることは確認した。

MODEL_SCHEMAとOUTPUT_SCHEMAの項目構造およびschema_version=extraction-1.0は維持。prompt/rule版は1.3。モデル名・APIキー・匿名サンプル・外部送信の許可範囲は変更していない。
